开机自启

以 --cpaclient-autostart 参数拉起，登录后直接进托盘、不弹窗口；核心由应用按上次的版本与配置自行启动。

托盘菜单四项与真实实现一致：WebUI / 设置 / 停止核心 / 退出；点「停止核心」看看状态怎么变

代理本身够好了，难的是每天把它跑稳

换架构要挑对包、改配置要重启、清一次 GitHub 限流能耗掉半小时。CPAClient 把这些琐碎收进一个 860×640 的窗口里，六件事各管一段。

一键准备核心

首次启动自动铺出 sandbox/bin·config·tmp 与默认 config.yaml，读运行时架构挑 CLIProxyAPI_版本_系统_架构 资产，解压后补 chmod +x；已有可执行文件就跳过，不重复下载。

版本切换与热更新

下拉列出上游最近 20 个版本，选完点「更新核心」即停核心、拉新包、再起；有新版本时输入框下方直接给提示。端口从 config.yaml 读，默认 8317。

统计不会丢

核心每 60 秒导出一次 usage 快照；重启或升级前先导后导，就绪 10 秒回灌、失败重试 8 次；刚启动的 20 秒锁住手动同步，避免把旧数据盖上去。

配置备份到 WebDAV

测试连接 / 立即备份 / 还原配置三个动作。backup.zip 装 config.yaml + usage.json + auth 目录凭据，远端自动分目录，最多留 20 版，按时间戳挑一个还原。

多端同步用量

家里和公司同一份统计：本地每 1 分钟检查、上传最短间隔 3 分钟；两边都改过就按时间戳择优，谁新听谁的，sync/ 下最多留 100 个版本。

常驻而不打扰

托盘四项菜单、左键唤回窗口、关窗可选最小化或直接退（退之前必停核心）、登录后自启且不弹框；主题随系统 / 日间 / 夜间三档即时生效。

三步跑起来

不用装 Docker、不用手搓命令行，第一次跑起来只需要一个 GitHub Token。

1

装应用

在 Releases 里挑对应架构的包解压运行：Windows windows_amd64.zip / windows_arm64.zip，macOS darwin_*.tar.gz，Linux linux_*.tar.gz。

构建未做代码签名与公证，macOS 首次打开请按系统的放行提示操作。
2

配 Token

首次启动会弹「需要 GitHub Token」。到 GitHub 建一个带 repo 权限的 Token 粘进去，版本列表与核心下载都靠它；不想留就用「本地保持 Token」开关，关掉即清空。

3

起核心、开 WebUI

确认版本后应用会自动下载并启动核心，概览卡的圆点变绿即就绪；点「WebUI」直接进 127.0.0.1:8317/management.html，密钥同步写在 config.yaml。

卡住的时候，多半是这四件事

拉取 Release 报 403

匿名访问 GitHub API 很容易撞限流。配一个带 repo 权限的 Token 再试；没配 Token 时版本列表也只会退化成当前已装版本。

WebUI 打不开

先看概览卡的运行圆点，再核对端口是不是 config.yaml 里那个；应用侧日志在 sandbox/app.log，超过 1MB 会自动截断保留尾部。

WebDAV 备份失败

地址必须 https:// 开头且不以 / 结尾，远端目录会自动追加 /CpaClient。命中服务端临时限流会按 10 → 20 → 30 分钟退避，不用一直点。

统计数对不上

刚启动或刚重启的 20 秒内手动同步是被锁住的，这是为了防止旧快照盖掉新数据；多端都改过时按时间戳择优，稍等一个同步节拍再看。

把代理跑成一件不用管的事

六个平台的安装包随 tag 一起发布；页面会自动认出你这台机器该下哪个。
